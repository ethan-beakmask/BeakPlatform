平台說明 - 企業管理員

本文件說明 BeakPlatform 的帳號等級、角色、權限架構與安全機制，供企業管理員參考。

帳號等級 (User Type)

每個帳號有且只有一個等級，決定此人在系統中的基本身分與可見範圍。

等級 代碼 說明
系統管理員 SYSTEM_ADMIN 平台維運人員，隸屬特殊企業 {{ SYSTEM_ORG_CODE }}。管理所有企業、主機設定、模組商店。不參與各企業內的業務操作。
企業管理員 ORG_ADMIN 企業內最高管理者。管理本企業的組織架構、帳號、角色、選單、模組設定。天生持有本企業內所有非系統級權限。
企業成員 EMPLOYEE 企業內一般使用者。可見範圍由管理員透過選單授權和角色指派決定。
外部廠商 EXTERNAL 非本企業人員（供應商、顧問等）。可見範圍最小，由管理員明確開放。
注意：等級之間互相獨立，不是「企業管理員 = 企業成員 + 更多權限」的關係。各等級看到的選單和功能由管理員分別配置。

預設角色

系統內建以下角色，企業管理員可在 /roles/ 自行增減角色。

企業級角色

管理本企業的組織與模組。

角色 職責
企業管理員 管理企業設定、組織架構、帳號、角色、模組配置
表單流程管理者 設計表單範本、設計流程、指定開發者

模組級角色

控制模組（如子系統開發模組）的存取層級，具有繼承關係。

角色 職責 繼承
模組管理員 管理模組成員、角色、刪除文章 -
模組作者 建立新文件、隱藏自己的文章 模組讀者
模組讀者 閱讀已開放的項目 -

成員級角色

組織架構中的職務角色，用於流程簽核與組織管理。

角色 說明
部門主管部門的負責人
部門成員隸屬於特定部門的企業成員
社群團長社群（跨部門群組）的負責人
群組成員隸屬於特定群組的成員
企業成員標準企業成員角色
受限制企業成員臨時雇員或受限帳號
外部顧問外部廠商的顧問人員
廠商代表外部廠商的代表
角色繼承：部分角色會自動包含下級角色的權限。例如「模組作者」自動擁有「模組讀者」的所有權限。繼承關係在 /roles/ 頁面可查看。

權限管理概觀

平台的權限分散在多個層面，各有不同的控制目標。企業管理員可透過「權限管理」(/permissions/) 進行統一檢視與管理。

權限層 管理位置 控制什麼
選單可見性 /menu/ 哪個帳號等級能看到哪些選單項目（如：企業成員能看到「表單中心」）
選單角色需求 /menu/ (角色欄) 選單項目需要持有哪些角色才能存取（如：需要「表單流程管理者」角色）
角色權限 (RBAC) /permissions/ 角色持有哪些具體操作權限（如：角色「表單流程管理者」持有 form_workflow.template.view）
選單最低門檻 程式定義 選單的最低權限要求（如：選單「表單範本」要求使用者持有 form_workflow.template.view）
帳號角色指派 /roles/ 哪些帳號持有哪些角色（如：張三擁有「表單流程管理者」角色）

選單可見性 vs. 存取權限

「看得到選單」和「能進入該頁面」是兩件不同的事。

步驟 檢查項目 通過條件
1 選單可見性 帳號等級在該選單的授權清單中
2 選單最低門檻 使用者持有選單要求的權限代碼（若有設定）
3 頁面存取 使用者持有該頁面所需的角色（由選單角色需求決定）
4 操作權限 使用者的角色擁有該操作所需的 RBAC 權限（如：建立、編輯、刪除）
常見問題：如果企業成員反映「選單看得到但點進去沒權限」，通常是步驟 1 通過但步驟 3 或 4 未配置。請至 /permissions/ 檢查衝突偵測結果。

企業管理員的天生權限

企業管理員（ORG_ADMIN）天生持有本企業內所有「企業級」和「模組級」權限，無需透過角色指派。

這代表：

  • 企業管理員不需要被加入任何角色就能操作所有企業內功能
  • 在 /permissions/ 的衝突偵測中，僅授權給 ORG_ADMIN 的選單不會被標記為缺少 RBAC 權限
  • 但「系統級」權限仍保留給系統管理員，企業管理員無法取得

權限管理建議流程

新增一個需要權限控制的功能時，建議依以下順序操作：

  1. /menu/ -- 設定選單可見性（勾選哪些帳號等級能看到）
  2. /roles/ -- 建立或選擇角色，指派角色給帳號
  3. /permissions/ -- 為角色配置所需的 RBAC 權限
  4. /permissions/ -- 使用衝突偵測功能確認配置完整

安全防護架構

平台採用多層防護設計，每一層獨立運作，即使某一層被繞過，後續層仍然保護系統。

層 名稱 作用 未通過的結果
1 全域認證攔截 所有請求必須先通過身分驗證，未登入者一律阻擋 導向登入頁面
2 路由層級檢查 各頁面依功能要求不同的帳號等級（如管理員專用頁面） 403 拒絕存取
3 網頁角色守衛 驗證使用者是否持有進入該頁面所需的角色 強制登出並記錄稽核日誌
4 資源權限檢查 驗證使用者是否有權執行特定操作（讀取、建立、編輯、刪除） 403 拒絕操作
5 企業資料隔離 每筆資料查詢都強制加入企業識別碼過濾，A 企業看不到 B 企業的資料 資料不可見

帳號安全

機制 說明
預設管理員帳號 企業建立時自動產生 admin 帳號。建議盡快建立個人管理員帳號後停用此預設帳號，儀表板會持續提醒。
帳號停用 vs 刪除 停用（is_active=false）：帳號無法登入但資料保留，可隨時恢復。刪除（is_deleted=true）：軟刪除，資料保留但完全不可見。
URL 安全識別碼 所有資源在 URL 中使用隨機產生的安全識別碼（secure_code），而非可猜測的流水號，防止未授權的資料存取。
稽核日誌 重要操作（登入、權限變更、資料異動）自動記錄稽核日誌，供事後追溯。

模組存取控制

模組（如表單流程、子系統開發）的存取受額外控制：

控制層 說明
合約驗證 企業必須持有該模組的有效合約才能使用。合約過期後模組不可見。
模組 ACL 企業管理員在 /admin/module-users/ 設定哪些企業成員可存取哪些模組。企業管理員本身自動擁有所有模組的存取權。

名詞對照表

名詞 英文 說明
帳號等級 User Type 帳號的基本身分分類：系統管理員、企業管理員、企業成員、外部廠商
角色 Role 可被指派給帳號的職務或功能身分，一個帳號可持有多個角色
角色繼承 Role Inheritance 子角色自動擁有父角色的所有權限
權限 Permission 可被授予角色的具體操作能力（如：檢視表單範本、編輯流程）
RBAC Role-Based Access Control 基於角色的存取控制。權限不直接授予帳號，而是授予角色，帳號透過持有角色間接獲得權限
選單可見性 Menu Permission 控制哪些帳號等級能看到哪些選單項目
選單角色需求 Menu Role Requirement 控制存取特定選單頁面需要持有哪些角色
選單最低門檻 Required Permission 選單項目設定的最低權限代碼，使用者必須持有該權限才能看到選單
企業隔離 Tenant Isolation 不同企業的資料完全隔離，互不可見
安全識別碼 Secure Code 系統內部用於識別資源的隨機字串，取代可猜測的流水號
模組 Module 掛載在平台上的獨立功能單元（如表單流程、子系統開發），透過合約授權使用
合約 Contract 企業與模組之間的授權關係，包含有效期限
稽核日誌 Audit Log 系統自動記錄的操作歷史，用於事後追溯與合規
衝突偵測 Conflict Detection /permissions/ 中的功能，自動檢查權限配置是否有遺漏或矛盾
