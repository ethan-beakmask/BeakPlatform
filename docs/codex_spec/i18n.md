## 多語系規範 I18N-01（新增任何 user-facing 字串時適用）

平台支援 zh-TW（原文即 key）+ en。**所有新的 user-facing 字串必須包翻譯函式。**

| 語境 | 寫法 | 帶變數 |
|------|------|--------|
| Python（flash / jsonify error / abort） | `from flask_babel import gettext as _` → `_('中文')` | `_('共 %(n)s 筆', n=x)` |
| Jinja2 模板 | `{{ _('中文') }}` | `{{ _('共 %(n)s 筆', n=x) }}` |
| JS（靜態檔、模板 script、Alpine 表達式） | `__('中文')`（i18n.js 全域） | `__('共 {n} 筆', {n: x})` |

### 禁止包裹（包了會出事，不是風格問題）

- **參與 `==` / `===` 比較的字串**——後端包了 `_()` 之後，前端比對同一字串即失效。
  代碼值如 `'partial'`、`'portal_data'`、`'all'`、`'TEXT'`、`'read'` 一律裸字串
- **機器可讀的 API 錯誤碼**（`no_valid_data`、`table_exists`、`write_failed`）——
  保持裸字串，中文對照放前端
- logger / console 訊息
- 寫入 DB 的資料值
- email 主旨與內文

### msgid 內的 `%`

字面 `%` 必須寫成 `%%`。flask_babel 一律做 % 插值，裸 `%` 直接 500。

### 傳給模板的顯示文字

不要在後端組好中文再傳給模板（那會變成裸字串且無法翻譯）。
後端傳 `None` 或代碼，**由模板決定顯示文字**：

```python
# 後端
banner = {'group': group_name if group_code else None}
```
```jinja2
{# 模板 #}
{{ _('以「%(g)s」身分', g=banner.group or _('不限群組')) }}
```

### 完成後必跑（漏跑等於沒做）

```bash
cd /opt/BeakPlatform-dev/backend
../venv/bin/pybabel extract -F babel.cfg -k _l -o translations/messages.pot . \
  ../modules/open_defense ../modules/vuln_lifecycle ../modules/spec_formulate \
  ../modules/nocode_builder ../modules/form_workflow
../venv/bin/pybabel update -i translations/messages.pot -d translations -l en
# 補翻 translations/en/LC_MESSAGES/messages.po 後
../venv/bin/pybabel compile -d translations
```

- **extract 必須帶齊上列全部模組目錄**——少帶任何一個，該模組的 msgid 會被打成
  obsolete 並喪失既有翻譯（已發生過事故）。新模組包裹後要加進此清單
- **`pybabel update` 產生的 fuzzy 配對幾乎全錯**，必須逐條重翻並清除 fuzzy flag。
  實例：「帳號權限」→ `Account limit`、「刪除節點」→ `node`、「電話」→ `Contact number`
- 收尾前確認 `grep -c '#, fuzzy' translations/en/LC_MESSAGES/messages.po` 為 **0**

### JS 字典

`backend/app/static/i18n/en.json`（zh 原文 → en，flat dict / `indent=1` / `sort_keys=True`）。
新增 `__()` 字串後要一併補進去，否則英文介面顯示中文。

### 獨立模板（不繼承 base.html）

需自行載入 i18n.js 與語系字典。`BkI18n` 是 top-level const 不掛 window，
JS 判斷用 `typeof BkI18n !== 'undefined'`。
