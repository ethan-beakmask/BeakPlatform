# 資安團隊角色設計建議（開放防禦模組）

> 對象：企業管理員（ORG_ADMIN）
> 前提：貴企業的合約已包含「開放防禦」（open_defense）模組

## 平台給你什麼

採購開放防禦模組後，貴企業自動獲得一個系統級預設角色：

| 角色代碼 | 名稱 | 授權內容 |
|---|---|---|
| `SECURITY_STAFF` | 資安人員 | 可見並進入「資安案件處置中心」，可簽核資安案件 |

這是刻意設計的**最小集合**：每個企業的 SOC 編制、輪值方式、簽核層級都不一樣，
平台不預設你的組織分工。把「資安人員」指派給所有需要碰資安案件的同仁即可運作；
需要分工時，再依下面的建議自行增設角色。

## 自行設計角色的操作路徑

1. **建立角色**：`帳號管理 → 角色管理`，新增角色（如 `SOC_L1`）
2. **綁定頁面可見性（鑰匙 2）**：`權限中央 → 功能視角 → 資安案件處置中心 → 角色存取需求 [編輯]`，
   勾選新角色
3. **指派人員**：`帳號管理 → 帳號角色`，將角色指派給值班同仁
4. **接上簽核流程**：在流程設計器中，把簽核節點的簽核人設為對應角色

注意：角色指派給 ORG_ADMIN 帳號無效果（管理員本來就 bypass 角色檢查），
請指派給同仁的 EMPLOYEE 帳號。

## 範例一：小型團隊（2~5 人，單一窗口）

不增設角色，直接使用預設的「資安人員」：

```
資安人員 (SECURITY_STAFF)   ← 全體資安同仁
  - 資安案件處置中心：可見、可簽核
```

流程簽核節點一律指向「資安人員」，誰值班誰處理。

> 想直接用現成的？`docs/guides/OD_WORKFLOW_VARIANTS.md` 提供兩個依編制設計好的
> 處置流程（3~8 人輪班的「SOC 團隊版」、單人 8 小時班的「小企業單人版」），
> 建置腳本會一併建立下面範例二用到的 `SOC_SUPERVISOR` 角色並綁好選單可見性。

## 範例二：分級 SOC（一線值班 + 主管覆核）

增設兩個角色，形成 L1 初判、主管對高風險案件覆核的兩級制：

```
資安人員 (SECURITY_STAFF)      ← 保留，作為「可進處置中心」的基底角色
SOC_L1「SOC 一線值班」          ← 輪值人員，負責初判與例行處置
SOC_SUPERVISOR「資安主管」      ← 高嚴重度案件的第二級簽核與封鎖決策覆核
```

搭配方式：

- 鑰匙 2：資安案件處置中心綁 `SECURITY_STAFF` + `SOC_L1` + `SOC_SUPERVISOR`
  （三者任一即可見）
- 流程：嚴重度低 → 簽核節點指向 `SOC_L1`；嚴重度高（如 severity >= 4 或建議封鎖）
  → 先 `SOC_L1` 初判、再 `SOC_SUPERVISOR` 覆核
- 人員同時持有 `SECURITY_STAFF` 與其分工角色，日後調整分工只動後者

## 設計原則

- **角色跟著職責走，不跟著人走**：命名用職責（值班、主管、鑑識），不要用人名
- **從最小集合開始**：先用「資安人員」跑起來，流程確定後再細分，避免一開始
  建一堆空角色
- **預設角色不要改用途**：「資安人員」是模組預設角色（系統級），請保持其
  「可進處置中心」的基底語意；分工語意放在自建角色上
