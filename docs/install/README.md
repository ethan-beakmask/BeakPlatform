# 安裝階段文件

**這個目錄的文件不依賴平台執行中。** 站內線上說明（`/help/`）要登入才看得到，
而安裝、初次登入這些階段還沒有可用帳號，所以做成可直接開啟的獨立 HTML。

| 檔名 | 什麼時候看 | 內容 |
|---|---|---|
| `first_login.html` | 安裝完成後、第一次登入前 | 為什麼有原始管理員 `admin@網域`、初次登入為何被強制導向設定頁、要填什麼、完成後為什麼會變成兩組帳號 |
| `ai_node.md` | 要用流程的「AI 分析」節點時 | 需要哪些前置條件、CLI 路徑與認證要設在哪個帳號、代理與內部憑證怎麼傳、錯誤訊息對照 |
| `os_node.md` | 要用流程的「OS 命令」或「檔案讀取」節點時 | 兩個節點各自的開關與白名單、sudoers 需求與風險、允許目錄的三層設定、輸出檔清理排程、設計者必知的三個邊界 |
| `edl.md` | 要把封鎖決策接到防火牆時 | 黑名單檔案的格式與內容規則、排程與設定、檔案分享與 HTTP 兩種取用方式、驗證步驟 |
| `defense_node.md` | 要架第二台主機當防禦端（WAF / IDS / 自動封鎖）時 | 兩台主機的分工、管制端發憑證一行指令、防禦端一鍵安裝參數、Cloudflare Tunnel 自動或手動設定、驗證與日常操作、換 IP、安全邊界、常見問題 |

## 怎麼開啟

檔案在安裝目錄底下，用瀏覽器直接開即可，不需要平台在跑：

```
<安裝目錄>/docs/install/first_login.html
```

`ai_node.md` 是純文字檔，直接用編輯器或 `less` 開啟即可。

在無桌面環境的伺服器上，可以複製到本機再開，或用文字瀏覽器閱讀。

## 為什麼不放在使用者手冊裡

`docs/manual/` 的內容同時餵給站內 `/help/` 與 MkDocs 站，兩者都需要
平台執行中（前者還要登入）。安裝階段兩個條件都不成立，
所以這份必須獨立於整套文件機制之外。
