# 安裝階段文件

**這個目錄的文件不依賴平台執行中。** 站內線上說明（`/help/`）要登入才看得到，
而安裝、初次登入這些階段還沒有可用帳號，所以做成可直接開啟的獨立 HTML。

| 檔名 | 什麼時候看 | 內容 |
|---|---|---|
| `reader_quickstart.md` | **第一次架練習環境先看這份** | 兩台主機（平台＋防禦節點）的最短安裝路徑：三行指令、三個檢查點、卡住對照表、重來方式 |
| `first_login.html` | 安裝完成後、第一次登入前 | 為什麼有原始管理員 `admin@網域`、初次登入為何被強制導向設定頁、要填什麼、完成後為什麼會變成兩組帳號 |
| `ai_node.md` | 要用流程的「AI 分析」節點時 | 需要哪些前置條件、CLI 路徑與認證要設在哪個帳號、代理與內部憑證怎麼傳、錯誤訊息對照 |
| `os_node.md` | 要用流程的「OS 命令」或「檔案讀取」節點時 | 兩個節點各自的開關與白名單、sudoers 需求與風險、允許目錄的三層設定、輸出檔清理排程、設計者必知的三個邊界 |
| `demo_data.md` | 要查看或佈建 node展覽館、或建立可登入的示範企業時 | 系統級 node展覽館、企業級 node 範例與示範企業的內容、佈建指令、登入驗證、移除方式與常見問題 |
| `api_trigger.md` | 要用外部 API 建立一張資安案件單時 | 在 UI 建 API Key、用 `bp_trigger.py --list` 找 `form_code`、用指令送單、錯誤碼對照 |
| `mail_smtp.md` | 要設定平台系統信寄送時 | 不裝 E-MailRelay，改在主機設定建立系統級 SMTP、設為預設、指定主要發信服務並測試寄送 |
| `edl.md` | 要把封鎖決策接到防火牆時 | 黑名單檔案的格式與內容規則、排程與設定、檔案分享與 HTTP 兩種取用方式、驗證步驟 |
| `ithome2026_waf.md` | 要架第二台主機當防禦端（WAF / IDS / 自動封鎖）時 | `install.sh --demo` 快速路徑、管制端發憑證一行指令、防禦端一鍵安裝、內網最小驗證、Cloudflare 對外公開選項 |
| `ithome2026_waf_standby.md` | 要把防禦端做成兩台熱備時 | 兩台主機三個 IP 的架構、為什麼切換點是 cloudflared 而不是 IP、`standby.sh` / `failover.sh` 用法、腦裂防護、切換驗證 |
| `ithome2026_waf_monitor.md` | 熱備架好之後，要自動發現現役節點死掉時 | 探測腳本的四段判定與三個易錯點、把巡檢做成表單流程的理由、無人回應時的逾時處置、heartbeat 看門狗、佈建與停止方式 |
| `os_file_write_node.md` | 要用流程的「OS 檔案寫入」節點時 | 三道開關、寫入目錄白名單、換行處理與追加語意 |

## 怎麼開啟

檔案在安裝目錄底下，用瀏覽器直接開即可，不需要平台在跑：

```
<安裝目錄>/docs/install/first_login.html
```

`ai_node.md` 是純文字檔，直接用編輯器或 `less` 開啟即可。

在無桌面環境的伺服器上，可以複製到本機再開，或用文字瀏覽器閱讀。

## 為什麼不放在使用者手冊裡

`docs/manual/` 的內容同時餵給站內 `/help/` 與 MkDocs 站，兩者都需要
平台執行中（前者還要登入）。安裝階段兩個條件都不成立，
所以這份必須獨立於整套文件機制之外。
