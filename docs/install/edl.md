# 防火牆黑名單（EDL）的產出與取用

**這是選用功能。** 平台會把「目前應該封鎖的 IP／網段」渲染成一個純文字檔，
供防火牆或其他設備定期抓取。沒有要接防火牆的話，本頁整份可以略過。

這份文件寫給**安裝與維運人員**，不需要平台在執行中就能閱讀。

---

## 一、它是什麼

EDL（External Dynamic List）是防火牆界通用的做法：防火牆定期去抓一個純文字檔，
**抓到的內容就是當下的政策**。檔案格式極簡，一行一筆位址，沒有別的東西。

平台產出的檔案就是這個格式：

```
198.51.100.7
203.0.113.0/24
2001:db8::1
```

**沒有註解、沒有標頭、沒有空行**，IPv4 在前、IPv6 在後，各自排序並去重。
之所以不寫註解，是因為只有部分設備支援 `位址 空格 註解` 的寫法，
加了註解就不再是「大部分設備都吃得下」的檔案。

## 二、內容從哪來

來源是平台的防禦決策（開放防禦模組寫入的封鎖決策）。一筆決策會出現在檔案裡，
必須同時滿足：

- 動作是「封鎖」，且目標型別是 IP、IPv6 或網段（網域、URL、雜湊不適用 EDL 格式）
- 尚未過期（決策的到期時間還沒到，或本來就沒有設到期）
- 沒有被撤銷，也沒有更晚的「解除封鎖」或「放行」決策覆蓋它

**過期直接依到期時間判斷**，不看決策的狀態欄位。這一點是刻意的：
在只接 EDL、沒有其他執行端的部署裡，決策狀態會一直停在「待處理」，
若依狀態判斷，過期的項目永遠不會從清單裡掉出去。

每個企業各有一份清單，彼此不混。

## 三、產出方式

一支排程程式每分鐘重新渲染一次全部企業的清單：

```
<安裝目錄>/scripts/cron/od_render_edl.py
```

建議的排程寫法（每分鐘，並用 flock 避免重疊執行）：

```
* * * * * <執行帳號> flock -n /tmp/od-render-edl.lock \
  <安裝目錄>/venv/bin/python <安裝目錄>/scripts/cron/od_render_edl.py \
  >> <log 目錄>/od_render_edl.log 2>&1
```

參數：

| 參數 | 用途 |
|---|---|
| （無） | 渲染全部企業並寫檔，成功後更新 heartbeat |
| `--dry-run` | 只計算不寫檔，也不更新 heartbeat |
| `--org <企業代碼>` | 只處理單一企業 |

**每次都是整份重算後原子替換**（先寫暫存檔再 rename），不是逐筆追加。
防火牆正在讀的時候不會讀到半截檔案。

**渲染過程若發生任何錯誤，程式不會寫檔，既有檔案原封不動保留。**
這一條很重要：空的 EDL 在防火牆語意上等於「解除全部封鎖」，
若查詢失敗就寫出空檔，一次資料庫故障會讓防線整個消失。

## 四、設定

兩個環境變數（`.env`）：

| 變數 | 說明 |
|---|---|
| `OD_EDL_OUTPUT_DIR` | 輸出目錄。未設定時預設是安裝目錄下的 `data/edl` |
| `OD_EDL_ALLOWED_IPS` | 允許透過 HTTP 抓取的來源，逗號分隔，可用單一位址或網段。**未設定＝一律拒絕** |

輸出的檔案路徑是：

```
<OD_EDL_OUTPUT_DIR>/<企業代碼>/blocklist.txt
```

## 五、兩種取用方式

### 檔案分享

把 `OD_EDL_OUTPUT_DIR` 指到一個已經分享出去的目錄即可（Samba、NFS、
或任何你既有的檔案分享機制），平台直接寫在那裡，不需要另外搬檔。
這條路適合「防火牆或管理者從網路磁碟讀取一個 txt」的既有作業方式。

### HTTP

平台提供一個公開端點：

```
<平台網址>/edl/<企業代碼>/blocklist.txt
```

- **必須**在 `OD_EDL_ALLOWED_IPS` 內的來源才拿得到；不在名單內、名單沒設定、
  企業代碼不存在、檔案還沒產生——**一律回 404**，不區分原因，
  避免對外洩漏哪個企業存在
- 端點有流量限制（每分鐘 60 次、每小時 1000 次），正常的防火牆輪詢遠低於此
- 回應會帶 `Cache-Control: no-store`，避免中間層快取住過期的清單
- 內容直接來自上一節那個檔案，**與檔案分享看到的是同一份**

企業代碼是不可枚舉的隨機字串，但它**不是**授權憑證——真正的存取控制是來源
位址白名單，請不要只依賴網址不外流。

## 六、驗證裝好了沒

```bash
# 1. 手動跑一次，看有沒有產出檔案
<安裝目錄>/venv/bin/python <安裝目錄>/scripts/cron/od_render_edl.py --dry-run

# 2. 正式跑一次並檢查檔案
<安裝目錄>/venv/bin/python <安裝目錄>/scripts/cron/od_render_edl.py
find <OD_EDL_OUTPUT_DIR> -name blocklist.txt -printf '%s\t%p\n'

# 3. 從白名單內的主機抓 HTTP 端點
curl -i <平台網址>/edl/<企業代碼>/blocklist.txt
```

檔案是 0 bytes 是正常的——代表該企業目前沒有生效中的封鎖。

拿到 404 時依序檢查：來源位址在不在 `OD_EDL_ALLOWED_IPS`、
企業代碼有沒有打錯、排程有沒有跑過（檔案存不存在）。
平台不會告訴你是哪一個原因，這是刻意的。
