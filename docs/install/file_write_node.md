# 「檔案寫入」節點的部署需求

適用對象：主機管理員、平台系統管理員。

流程設計者不需要讀這一篇，但**第四節必須轉達給他們**——那三件事平台修不了，
只能靠設計流程的人自己處理。

「檔案寫入」（`FileWrite`）讓流程把一段字串**追加**到主機上某個檔案的結尾。
典型用途是寫文字型的 log，或把流程各步驟的結果組合成一份輸出檔。

---

## 一、先讀這段：三個主機側節點的授權是各自獨立的

平台有三個會碰到主機檔案系統的節點，能力由低到高：

| 節點 | 能做什麼 |
|---|---|
| 檔案讀取（`FileRead`） | 只讀，不經 shell，鎖在允許目錄內 |
| **檔案寫入（`FileWrite`）** | **只能在允許目錄內的一般檔案結尾追加字串** |
| OS 命令（`OsExecutor`） | 在平台主機執行命令 |

**三者的開關與企業授權完全分開，不會互相帶動。**
可讀不等於可寫：`file_read_base_dirs` 與 `file_write_base_dirs` 是兩份清單，
必須各自設定。企業可以只取得「把結果寫進一個 log 檔」的能力，
而不必同時取得讀取主機檔案或執行命令的權限。

### 「檔案寫入」不能做的事

它**不能**覆寫既有內容、不能刪除檔案、不能建立目錄、不能改權限、
不能寫到符號連結、不能寫到目錄或裝置檔，也不經過 shell（沒有命令注入面）。
它唯一會改動既有檔案的動作，是把**檔案結尾原有的換行符號**清掉——
這是刻意的行為，見第三節。

---

## 二、四個啟用步驟

安裝完成後這個節點是**全部關閉**的：`.env` 沒開、節點在設計器裡不出現、
只有系統企業獲得授權、允許目錄是空清單。四道都打開才寫得到任何檔案。

### 1. 設定 `.env`

```bash
# <安裝目錄>/.env
FILE_WRITE_NODE_ENABLED=1
```

改完要重新啟動節點執行器服務。**重新啟動前請先確認沒有流程正在執行中**，
否則執行中的節點會被中斷。

### 2. 讓節點在設計器裡出現

```sql
UPDATE workflow_node_definitions SET is_active = true WHERE node_type = 'FileWrite';
```

### 3. 指定允許的企業

```bash
venv/bin/python scripts/node_grant.py grant FileWrite <企業識別碼或企業代碼>
venv/bin/python scripts/node_grant.py revoke FileWrite <企業識別碼或企業代碼>
```

也可以用平台介面的「權限管理 → 節點授權」頁面（限系統管理員）。

等效的 SQL：

```sql
INSERT INTO workflow_node_org_grants (
    secure_code, node_type, org_secure_code, granted_by_name,
    created_at, updated_at, is_deleted
)
SELECT
    substr(md5(random()::text || clock_timestamp()::text), 1, 32),
    'FileWrite',
    '<企業識別碼>',
    'manual_sql',
    NOW(),
    NOW(),
    FALSE
WHERE NOT EXISTS (
    SELECT 1
      FROM workflow_node_org_grants
     WHERE node_type = 'FileWrite'
       AND org_secure_code = '<企業識別碼>'
       AND is_deleted = FALSE
);
```

撤銷是軟刪除，再授權會新增一列，所以這張表本身就是授權歷史。

### 4. 指定允許寫入的目錄

```sql
-- 全平台允許寫入的根目錄（預設空清單 = 寫不到任何檔案）
UPDATE system_settings SET value = '["/var/log/myapp"]'
 WHERE key = 'file_write_base_dirs';

-- 選填：再針對個別企業收窄成子集合（沒設定該企業就沿用上面的全平台清單）
UPDATE system_settings SET value = '{"<企業識別碼>": ["/var/log/myapp"]}'
 WHERE key = 'file_write_org_base_dirs';
```

#### 允許目錄是三層取交集

```
平台允許目錄  ∩  該企業允許目錄  ∩  節點設定的目錄  →  實際可寫範圍
```

路徑檢查會先解開中間層的符號連結再判定，所以在允許目錄裡放一個指向系統檔案的
符號連結是無效的；**目標檔案本身是符號連結時也一律拒絕**（不論它指向哪裡）。

#### 選允許目錄的原則

- **不要指向平台自己的資料目錄、設定檔目錄或程式碼目錄。**
  這個節點會追加內容到檔案結尾，追加到設定檔就等於改壞設定
- 建議開一個專用目錄，只放給流程寫的輸出檔
- 目錄的擁有者要是平台服務跑的那個作業系統帳號，且該帳號要有寫入權限。
  新建的檔案權限是 `0640`
- **不要用網路檔案系統（NFS）**：平台用檔案鎖避免多個流程同時寫入時互相蓋掉，
  而檔案鎖在部分 NFS 實作上沒有作用

---

## 三、換行是怎麼處理的（最容易誤解的部分）

每次寫入之前，平台會把**檔案結尾原有的換行符號全部清掉**，
Windows（CRLF）、Linux（LF）、舊 Mac（CR）三種都算，有幾個清幾個。
然後才依照節點上的兩個勾選補上換行：

- 「內容前面加一個換行」
- 「內容後面加一個換行」

檔案結尾以外的內容**一個位元組都不會被改動**，也不會轉換檔案原本的編碼、
不會加 BOM、不會加時間戳。

### 所以：要一筆一行的 log，兩個勾選都要開

只勾「後面」的話，下一次寫入會先把這個換行清掉，結果會全部黏成同一行：

```
只勾「後面」        →  第一筆L1第二筆L2第三筆L3
兩個都勾            →  第一筆L1
                       第二筆L2
                       第三筆L3
兩個都不勾          →  直接接在最後一個字後面（適合組合字串）
```

檔案是空的時候，「前面加換行」不會生效（否則檔案開頭會多一個空行）。

## 四、設計流程的人必須知道的三件事

**請轉達給流程設計者。**

### 1. 流程管理頁顯示綠燈，不代表檔案真的寫成功

這個節點失敗時**不會**讓流程節點變成失敗狀態。原因是平台對失敗的節點會自動
重試三次，而「追加字串」重跑三次就會寫進三筆重複資料——對寫檔來說，
自動重試比失敗本身更糟。

所以判斷成敗要看**結果變數**，不是看流程管理頁的狀態：

| 結果變數 | 內容 |
|---|---|
| `<前綴>_result` | `ok`／`exception`／`timeout` |
| `<前綴>_error_kind` | 失敗原因代碼（見下表） |
| `<前綴>_bytes_written` | 實際寫入的位元組數 |
| `<前綴>_trimmed_bytes` | 被清掉的結尾換行數 |
| `<前綴>_size_before` / `_size_after` | 寫入前後的檔案大小 |
| `<前綴>_created` | 這次是否新建了檔案 |
| `<前綴>_file_path` | 實際寫入的完整路徑 |

**建議在「檔案寫入」節點後面接一個分支節點，判斷
`${v.<前綴>_result}` 是不是 `ok`**，失敗就發通知，不要讓流程默默走完。

失敗原因代碼：

| 代碼 | 意思 |
|---|---|
| `not_authorized` | 節點未啟用，或這家企業沒有被授權使用這個節點 |
| `path_denied` | 路徑不在允許目錄內、是符號連結、不是一般檔案，或父目錄不存在 |
| `file_not_found` | 關掉了「自動建立」而檔案不存在 |
| `permission_denied` | 作業系統層的權限不足 |
| `file_too_large` | 寫入後會超過節點設定的檔案大小上限 |
| `encode_error` | 內容無法用指定的編碼表示 |
| `bad_config` | 節點設定不合法（結果變數名、編碼名等） |
| `lock_timeout` | 等不到檔案鎖（其他流程正在寫同一個檔） |
| `io_error` | 其他輸入輸出錯誤（例如磁碟寫滿） |

### 2. 不會自動建立目錄

「檔案不存在時自動建立」只建**檔案**，不建目錄。目標檔的上層目錄不存在時
一律失敗，要請主機管理員先把目錄建好。

### 3. 檔案會一直長大，平台不會自動清

節點設定有「檔案大小上限」，超過就拒絕寫入並回 `file_too_large`——
**它是煞車，不是清理機制**。長期使用的輸出檔請由主機管理員安排輪替
（例如系統的 logrotate），否則有一天流程會突然開始失敗。

## 五、常見問題

**Q：設計器裡找不到「檔案寫入」節點。**
依序檢查：節點是否 `is_active = true`、這家企業是否已授權
（`scripts/node_grant.py list`）。前兩步任一沒做，工具列上就不會出現。

**Q：節點看得到、流程也跑完了，檔案卻沒有內容。**
看結果變數 `<前綴>_result` 與 `<前綴>_error_kind`。最常見的是
`not_authorized`（`.env` 沒開或執行器沒重新啟動）與 `path_denied`
（允許目錄還是空清單，或節點填的目錄不在平台清單的交集內）。

**Q：多個流程同時寫同一個檔案會不會壞掉？**
不會。平台用排他檔案鎖，同一時間只有一個流程能寫，其他的會等待；
等超過節點設定的逾時就回 `lock_timeout`（不會寫進去，也不會弄壞檔案）。
前提是目錄在本機檔案系統上，不是 NFS。

**Q：可以寫非 UTF-8 的檔案嗎？**
可以，節點上有「編碼」欄位（例如 `big5`）。既有內容不會被轉碼。
但**不支援 UTF-16 / UTF-32**——結尾換行的判斷是位元組層級的，
在那些編碼下會誤判並破壞檔案，所以平台直接拒絕。
內容裡有指定編碼表達不了的字時，平台會**拒絕寫入**而不是寫成問號。

## 六、不需要安裝的東西

這個節點只用 Python 標準函式庫，不需要額外套件、不需要 sudo 規則、
不需要額外的系統服務。
