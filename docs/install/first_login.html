BeakPlatform 初次登入設定

本文件刻意做成單一 HTML 檔，不需要平台在執行中就能閱讀。 因為它要處理的正是「系統剛裝好、還沒有任何可用帳號」的那個時間點， 此時站內線上說明還進不去。

為什麼會有這一步

安裝完成後，系統會建立一組原始管理員帳號，格式是 admin@貴公司網域。這組帳號的存在是為了解決一個先後次序問題：

要建立員工帳號，必須先有管理員登入；
但要有管理員，又必須先建立帳號。

原始管理員就是打破這個循環用的引導帳號。但它的名稱是可推測的—— 任何人都猜得到某家公司的管理員帳號叫 admin@ 開頭， 這在對外開放的環境是明確的風險。

因此系統的設計是：原始管理員只用來完成一次設定，之後立刻停用。 您第一次登入時，系統會強制導向設定頁，不做完就不能使用其他功能。 這不是可以略過的步驟。

操作步驟

1. 用安裝時取得的帳密登入

安裝腳本在收尾時會印出這兩項：

系統企業: 貴公司網域
管理員:   admin@貴公司網域
密碼:     (安裝時設定，首次登入須變更)

忘記密碼時無法自助重設（此時還沒有第二個管理員可以協助）， 只能由主機管理者重新執行安裝腳本的初始化步驟。請在安裝當下就記下來。

2. 系統自動導向初始設定頁

登入後會直接進入設定頁（網址結尾是 /admin/initial-setup）， 此頁沒有選單、也無法用網址跳過。

3. 填寫您本人的員工資料

這一步建立的是「您這個人」的員工帳號，不是另一組管理員帳號。

欄位必填說明
本國姓名是中文姓名
英文姓名是護照或公司慣用的英文名
帳號是登入用的識別名稱，例如 ethanyu
用戶編號是沒有預設編號規則時必須自行填寫
密碼是需符合系統的密碼強度規則，需輸入兩次
暱稱、備用信箱、行動電話否可事後在個人設定補上

4. 送出後系統自動完成三件事

  1. 建立您的員工帳號（就是您剛填的那組）
  2. 自動產生一組綁定的管理員帳號，名稱是 admin-您的帳號（例如 admin-ethanyu）
  3. 停用原始管理員 admin@…，該帳號自此無法再登入

從此您有兩組帳號，這是刻意的設計。 日常作業（填單、簽核、看報表）用員工帳號； 只有在需要管理設定（建立部門、指派角色、模組授權）時才切換到 admin- 開頭的管理員帳號。

分開的理由很單純：管理員權限很大，天天掛在上面等於天天把最大權限暴露在外。

做完之後

設定完成後就會進入儀表板，站內說明（右上角 [?] 或選單的「使用者手冊」） 從這時起可以正常使用，後續操作請看那裡。建議的下一步順序：

  1. 建立部門與組織單位
  2. 建立職等、職系、職稱
  3. 設定核決權限
  4. 建立其他員工帳號並指派角色

常見問題

可以不要建立員工帳號，直接繼續用 admin@ 嗎？

不行。系統會持續把您導回設定頁。這是安全設計，沒有開關可以關閉。

已經有人做過設定了，我登入卻沒看到這頁

表示該企業已經有綁定的管理員帳號，設定流程已完成， 原始管理員也已停用。請向完成設定的那個人索取您的帳號。

填錯了可以重來嗎？

姓名、暱稱、聯絡方式等資料可以事後在「個人設定」或「企業成員帳號」修改。 但帳號名稱與連帶產生的 admin- 帳號名稱無法變更， 送出前請確認。

忘記管理員密碼

此時系統中通常還沒有第二個管理員可以協助重設。 請聯絡主機管理者從伺服器端處理。

不要反覆嘗試猜測密碼。 系統有登入失敗鎖定機制，連續失敗會鎖住帳號， 在只有一個管理員的階段會讓情況更難處理。
