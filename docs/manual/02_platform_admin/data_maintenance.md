# 資料維護

這一頁的三個工具都是**永久刪除**，沒有復原機制，也不會進資源回收桶。
動手之前先看清楚三者清的東西完全不同。

| 工具 | 清什麼 | 什麼時候用 |
|---|---|---|
| 硬刪除已軟刪除的企業 | 被標記刪除的企業，連同它在所有資料表裡的資料與企業本身 | 客戶終止合作、確定不再復原 |
| 清除標記刪除的資料 | 各資料表中被標記刪除的**個別記錄**（帳號、角色、部門等），與企業存不存在無關 | 定期整理，回收被刪掉的舊資料 |
| 清理企業孤兒資料 | 指向**已經不存在的企業**的殘留記錄 | 過去刪企業時漏清的殘留，或例行體檢 |

這一頁清的不只是資料庫記錄。硬刪除企業時，企業上傳的檔案、加密檔案目錄與
EDL 黑名單目錄會跟著一起清掉；「清理企業孤兒資料」另外可以掃描沒有對應企業的
檔案與目錄。

「刪除企業」本身是兩段式的：在企業與合約管理頁按刪除只是**標記刪除**，
企業從清單上消失、成員無法登入，但資料都還在，隨時可以請開發人員救回。
資料真正消失是在這一頁按下[執行硬刪除]之後。

!!! abstract "作業：永久刪除已停用的企業"
    **MENU**：主機管理 ／ 資料維護

    1. 看「硬刪除已軟刪除的企業」卡片列出的待刪企業與涉及資料表
    2. 確認名單無誤後按 [執行硬刪除]
    3. 在確認視窗按 [確定]
    4. 看結果訊息：**綠色**代表全部刪除完成；**紅色**代表有資料表失敗

!!! abstract "作業：清理指向已不存在企業的殘留"
    **MENU**：主機管理 ／ 資料維護

    1. 在「清理企業孤兒資料」卡片按 [掃描]
    2. 先看「孤兒企業識別碼」——確認這些識別碼確實是已經刪掉的企業
    3. 再看「涉及資料表」與合計筆數
    4. 按 [執行清理]，在確認視窗按 [確定]

!!! abstract "作業：清理沒有對應企業的實體資源"
    **MENU**：主機管理 ／ 資料維護

    1. 在「清理企業孤兒資料」卡片的「實體資源」區塊按 [掃描實體資源]
    2. 檢查列出的無主上傳檔案、孤兒加密檔案目錄、孤兒 EDL 目錄，確認都是已經
       刪掉的企業留下的
    3. 按 [執行實體清理]，在確認視窗按 [確定]
    4. 「需自行以 CLI 處理」那一段不會被這個按鈕清掉，要另外照下一節的說明處理

## 結果要看顏色，不要只看有沒有跑完

硬刪除與孤兒清理都會逐張資料表處理，單張失敗不會中斷其他表。
所以「跑完了」不等於「刪乾淨了」：

- **綠色訊息**：全部成功，可以直接看刪除明細
- **紅色訊息 ＋ 失敗資料表清單**：有資料表沒刪成功，該企業**可能還在系統裡**

出現紅色時把失敗清單提供給開發人員，不要重複按[執行硬刪除]試圖硬闖。

## 企業獨立資料庫不會自動刪除

如果企業有獨立資料庫，畫面會列出資料庫名稱、原因與建議指令，但**不會**提供
自動刪除的按鈕。這是刻意的設計：刪掉整個資料庫的風險等級高於刪掉資料表記錄
或檔案，必須由系統管理員登入伺服器終端機、自行確認後執行。

指令格式通常如下，實際資料庫名稱請以畫面列出的內容為準：

```bash
sudo -u postgres dropdb <資料庫名>
```

## 掃描出來的識別碼要先確認

孤兒清理是依「這筆記錄掛的企業識別碼在企業名單裡找不到」判定的。
掃描結果會先列出所有孤兒的企業識別碼與筆數，就是要讓你在刪除前對一次：

- 認得出來是已經刪掉的客戶 → 可以清
- 出現不認得、或看起來像代碼而不像識別碼的值 → 先找開發人員確認，
  那通常代表某支程式把資料寫錯欄位，直接清掉會掩蓋問題

## 三個常見誤解

**「清除標記刪除的資料」不會刪掉企業。**
它處理的是各資料表裡被標記刪除的個別記錄；企業本身要走硬刪除。

**硬刪除不挑企業。** 它一次處理所有被標記刪除的企業，沒有逐一勾選的選項。
只想刪其中一家時，先確認其他企業不在待刪名單上。

**硬刪除企業時，檔案與目錄會一起清掉。** 企業上傳的檔案、加密檔案目錄與
EDL 黑名單目錄都由系統清理；只有企業獨立資料庫不會自動刪除，要由系統管理員
依畫面列出的指令人工處理。
