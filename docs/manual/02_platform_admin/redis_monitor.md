# Redis 監看

平台把**登入工作階段**、**登入與 API 的速率限制計數**、**檔案下載的一次性代碼**放在 Redis。
這一頁讓你不必登入主機就能看它的健康狀態，**全部唯讀**，不能改設定也不能刪 key。

!!! abstract "作業：確認 Redis 正常"
    **MENU**：主機管理 ／ Redis監看

    1. 看標題列右側是「Connected」
    2. 「總覽」分頁看記憶體使用、連線數、命中率

!!! abstract "作業：查某一類 key"
    **MENU**：主機管理 ／ Redis監看

    1. 切到「Key 瀏覽」分頁
    2. 下拉選資料庫編號，輸入樣式（例如 `dev_session:*`），按 [搜尋]
    3. 點某一列的眼睛圖示看內容

## 四個分頁

| 分頁 | 看什麼 | 何時更新 |
|---|---|---|
| 總覽 | 版本、運行時間、記憶體、連線數、每秒指令數、命中率、碎片率、持久化狀態、各資料庫 key 數 | 停在這個分頁時每 30 秒自動刷新 |
| Key 瀏覽 | 依樣式掃描 key，顯示型別、剩餘存活時間、佔用記憶體，可看單一 key 的值 | 按 [搜尋] 才查 |
| 慢查詢 | Redis 自己記錄的慢指令，最近 50 筆 | 按 [重新整理] 才查 |
| 完整 INFO | Redis INFO 指令的全部欄位 | 與總覽同步 |

## 畫面上看不出來的規則

- **不同用途的資料可能在不同編號的資料庫**。「總覽」的 Keyspace 表列出哪幾個編號有資料；
  「Key 瀏覽」預設查 db0，要看別的編號得手動切換下拉
- **每次搜尋只掃 50 筆**，底下的 [載入更多...] 接著掃下一批。這是逐段掃描，不會一次列出全部，
  也不會拖垮 Redis
- **看到的值可能被截斷**：字串超過一萬個字元、清單／集合／雜湊超過 100 個元素只顯示前段，
  畫面會標「（已截斷）」；串流型別不支援預覽
- 樣式最長 100 個字元
- 剩餘存活時間顯示「PERSIST」表示永不過期，「EXPIRED」表示剛好在你查詢時過期了
- 慢查詢的耗時超過 10 毫秒標黃、超過 100 毫秒標紅；門檻是 Redis 自己的設定，
  平台不會改它
- 只有「總覽」分頁會自動刷新，切到其他分頁後就停了

!!! warning "Key 內容可能含有登入者的個人資料"
    工作階段 key 裡存的是使用者登入後的狀態。這一頁只限系統管理員，
    但螢幕分享或截圖時請避開「Key 瀏覽」的內容區。

## 常見問題

**標題列顯示「Disconnected」或「Redis 連線失敗」。**
平台連不上 Redis。此時**使用者會無法登入**（工作階段存不了），速率限制會退回記憶體模式繼續放行。
這是主機層問題，到主機上檢查 Redis 服務。

**命中率一直是 100%，正常嗎？**
正常。平台對 Redis 的用法幾乎都是「寫入後讀取自己寫的東西」，很少讀不到。

**記憶體碎片率很高。**
資料量小的時候這個數字本來就會偏高，沒有實際意義。只有在記憶體使用量大且碎片率持續大於 1.5 時才需要處理。
