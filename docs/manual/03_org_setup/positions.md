# 職位設定

一筆職位＝**某位成員、在某個部門、以某個職稱任職**的紀錄，可以再註記類型（主要／兼任／代理／臨時）與生效期間。一個人可以有好幾筆。

!!! abstract "作業：指派職位"
    **MENU**：職級職稱 ／ 職位設定

    1. 按 [新增職位]
    2. 選成員、職稱、部門，選類型；需要的話勾「部門主管」、填生效與失效日期
    3. 按 [建立職位]

!!! abstract "作業：查看、修改、刪除"
    **MENU**：職級職稱 ／ 職位設定

    1. 該列按 [查看] 看詳情，或 [編輯] 修改
    2. 編輯頁改完按 [儲存]；要停用就取消勾選「啟用」
    3. 要刪除在編輯頁最下方按 [刪除此職位]，會再確認一次

## 直屬主管不在這裡設定

直屬主管由[部門設定](departments.md)的部門主管推導；本人就是部門主管、或所屬部門職缺時，會往上一層部門找。
職位詳情頁會顯示推導結果供核對。流程要使用直屬主管時，要放一顆[人事資料取值節點](../04_form_workflow/hr_lookup_node.md)，
它會把申請人的直屬主管寫成變數 `hr_direct_manager`，簽核節點的簽核人選「動態（從變數取）」填這個名字即可。

另一個容易混淆的地方：**職位裡的「部門」與帳號本身的「所屬部門」是兩個欄位**。
流程用「部門」指定簽核人時，讀的是帳號的所屬部門（在[企業成員帳號](users.md)設定），不是這裡的職位部門。

## 畫面上看不出來的規則

- 成員、職稱、部門三個必選。職稱下拉只列啟用中的職稱並附上職等名稱；
  部門下拉列的是[組織單位](units.md)裡所有啟用中的單位，不限部門這一層
- **成員建立後不能改**，指派錯人就刪掉重建
- 一個人可以有多筆職位。系統不限制「主要職位」只能有一筆，也不檢查同一人同一部門重複指派
- **失效日到了不會自動停用**，列表上照樣顯示啟用；到期要自己取消勾選「啟用」或刪除
- 詳情頁的「直屬主管（依部門推導）」是唯讀的計算結果，改部門主管要去部門設定
- 生效日不填就是今天。兩個日期都只是紀錄，不影響任何判斷
- 刪除職位沒有任何前置檢查
- 列表可點表頭排序，最多顯示最新的 100 筆

## 常見問題

**職稱下拉裡沒有我要的職稱。**
它被停用了，或還沒建。到[職稱設定](job_titles.md)確認。

**要幫某人換職稱。**
直接編輯那一筆改職稱即可；要保留歷史就把舊的那筆停用或填失效日，再新增一筆。
