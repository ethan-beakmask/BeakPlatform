# 企業系統設定

這一頁集中了**整家企業共用**的設定：登入頁長什麼樣、密碼要多強、通知寄給誰、
用哪個郵件伺服器寄。左側是八個分類，右側是該分類的內容。
**多數欄位改完即存**（勾選框與下拉選單一改就寫入，畫面下方會出現「已儲存」），
沒有整頁的儲存按鈕。

| 分類 | 影響誰 |
|---|---|
| 企業資訊 | 登入頁顯示的 Logo |
| 登入頁面顯示 | 企業成員與外部廠商各自的登入頁要不要露出 Logo 與企業名稱 |
| 一般設定 | 語系、時區、顯示名稱、帳號命名規則、能否自行改個人資料 |
| 密碼政策 | 所有帳號設定密碼時的強度檢查，以及登入失敗鎖定 |
| 登入安全欄位 | 登入頁三格「驗證碼」各自的用途 |
| 收件人群組 | 流程寄信時「寄給哪一群人」的名單 |
| SMTP 郵件 | 流程 Email 節點用哪台郵件伺服器寄 |
| Telegram | 流程 Telegram 節點用哪個 Bot、哪個頻道 |

!!! abstract "作業：上傳企業 Logo"
    **MENU**：系統管理 ／ 系統設定 ／ 企業資訊

    1. 按 [上傳 Logo]，選圖檔
    2. 上傳完成後畫面直接顯示預覽；要換就再按 [更換 Logo]

!!! abstract "作業：指定登入頁哪一格是密碼"
    **MENU**：系統管理 ／ 系統設定 ／ 登入安全欄位

    1. 在「員工登入」區塊，把密碼、地雷、救助三個用途各指定給一格驗證碼
    2. 填救助關鍵字（留空等於不啟用救助）
    3. 「廠商登入」區塊照同樣方式另外設定
    4. 通知所有使用者：哪一格才是密碼

!!! abstract "作業：建立收件人群組"
    **MENU**：系統管理 ／ 系統設定 ／ 收件人群組

    1. 按 [+ 新增群組]，填群組名稱
    2. 左側點部門（可勾「含子部門」）或個別用戶加入右側名單
    3. 按儲存；之後可按該群組的預覽看目前會寄給誰

!!! abstract "作業：新增 SMTP 或 Telegram 設定組"
    **MENU**：系統管理 ／ 系統設定 ／ SMTP 郵件（或 Telegram）

    1. 按 [+ 新增設定]，填名稱與連線資料
    2. 儲存後在清單上按 [測試] 確認連得上
    3. 有多組時把常用的那組勾「設為預設」

## 企業資訊

- **企業名稱、網域、帳號上限在這裡改不了**，那是系統管理員在建立企業時設定的。
  帳號上限只計企業成員與外部廠商帳號，管理員帳號不計入
- Logo 限 2MB，接受 PNG、JPG、GIF、SVG、WebP
- **Logo 是公開資源**：它顯示在登入頁，登入之前就看得到。不要拿內部文件截圖當 Logo
- SVG 檔在登入頁顯示正常，但直接用網址開啟會變成下載檔案，這是刻意的安全設計

## 登入頁面顯示

四個開關預設全開。關掉的用途只有一個：**不讓人從登入頁認出這是哪家公司**。
企業成員登入頁與外部廠商登入頁各自獨立，可以只隱藏對外那一頁。

## 一般設定

- **企業常用語系**是預設值，使用者在個人設定選了自己的語系就以個人為準。
  改了之後要重新整理頁面才會看到選單標題換語言
- **企業主要時區**同樣是預設值，個人設定的時區優先。資料庫一律以 UTC 儲存，
  這個設定只影響顯示
- **顯示名稱**決定新建帳號時用哪個欄位當顯示名稱，**只影響之後建立或編輯的帳號**，
  已存在的帳號不會回頭改名
- **帳號姓名連接符號**只在新增帳號時用來產生建議帳號（一律小寫），
  對既有帳號沒有影響
- 關閉「允許用戶修改個人資料」後，使用者在個人設定只能看不能改，**密碼變更不受影響**

## 密碼政策

出廠預設是**啟用**：至少 12 碼、大小寫數字符號四種都要、最近 5 次密碼不可重複、
連續錯 5 次鎖 15 分鐘，之後每次鎖定時間加倍（上限 24 小時）。

畫面上看不出來的三件事：

- **關閉密碼政策會連登入失敗鎖定一起關掉**。鎖定機制屬於政策的一部分，
  沒有辦法只留鎖定、不檢查強度
- 政策改嚴之後，**既有使用者不會被要求立刻改密碼**。新規則在下一次有人設定密碼時才檢查：
  新建帳號、使用者自己改密碼、管理員重設密碼都算
- 帳號被鎖時，等鎖定時間過去會自動解除；急用時由管理員在企業成員帳號重設密碼即可

畫面上那條「尚未設定 SMTP」的黃色提示，檢查的只是本頁有沒有啟用中的 SMTP 設定組。

## 登入安全欄位

登入頁固定有三格外觀相同的「驗證碼」，這裡決定每一格的用途，三格用途不能重複：

| 用途 | 使用者輸入了東西會怎樣 |
|---|---|
| 密碼欄位 | 當成密碼驗證 |
| 地雷欄位 | **一律登入失敗**，就算密碼正確也一樣 |
| 救助欄位 | 內容含有救助關鍵字時，寄「登入救助警報」給全部啟用中的管理員，登入本身照常進行 |

- 員工登入與廠商登入分開設定，兩邊可以配置得不一樣
- 救助關鍵字不分大小寫，欄位內容**包含**關鍵字就算觸發；留空表示不啟用救助
- 警報信寄到每位管理員的「備用 Email 1」，沒填的才寄主信箱。信裡有觸發帳號、來源 IP 與時間，
  不會告訴當事人已經觸發
- 登入回應固定有幾秒延遲，成功失敗都一樣，這是刻意的，不是系統變慢

!!! warning "改完一定要通知使用者"
    哪一格是密碼**不會顯示在登入頁上**。沒被告知的人會用猜的，猜錯就是踩地雷，
    連續幾次就被鎖定。換設定之前先想好怎麼把「第幾格」傳達給所有人。

## 收件人群組

- 群組是給流程的 Email 節點用的：設計流程時選群組，不必逐一挑人
- 成員來源可以是部門（含或不含子部門）或個別用戶，**寄信時才解析成實際名單**，
  之後部門人員異動會自動反映，不用回來改群組
- 寄到每個人的「備用 Email 1」，沒填的才用主信箱。使用者可在個人設定填備用信箱
- 停用中的帳號不會收到信

## SMTP 郵件與 Telegram

- 這兩區的設定組是給**流程節點**用的。流程設計者在 Email 或 Telegram 節點上挑一組，
  沒挑時用勾了「設為預設」的那組
- 忘記密碼信、管理員密碼重設通知、登入救助警報這類**系統信不走這裡的 SMTP 設定**，
  由平台主機上的郵件轉發服務寄出，那部分由系統管理員負責
- 編輯 SMTP 設定時密碼欄留空表示不修改
- Gmail 開了兩步驟驗證的帳號要用「應用程式密碼」，不是登入密碼
- Telegram 的 Token 從 BotFather 取得；一個設定組可以有多個頻道，
  流程節點是以「設定組 ＋ 頻道名稱」來指定送到哪裡
- 儲存後記得按 [測試]，設定錯誤在這裡就會看到，不會等到流程跑起來才發現

## 常見問題

**改了時區，某些畫面的時間還是不對。**
使用者個人設定的時區優先於企業設定，請他檢查個人設定；瀏覽器要重新整理。

**新建的帳號顯示名稱不是我要的欄位。**
先改「顯示名稱」設定再建帳號。設定只影響之後的帳號，之前建的要逐一編輯。

**使用者說登入一直失敗，密碼明明是對的。**
先問他密碼填在第幾格。填到地雷欄位會一律失敗，而且連續失敗會觸發鎖定。

**收件人群組預覽有人，流程卻沒寄給他。**
確認流程節點選的是這個群組，以及該帳號沒有被停用。名單是寄信當下才解析的。
