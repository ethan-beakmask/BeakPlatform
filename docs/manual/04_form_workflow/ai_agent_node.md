# AI 分析節點

把流程裡的一段資料（原始 HTTP request、案件欄位、使用者填的內容）交給 AI 判讀，
結果寫進流程變數，並可插入一筆註記給後面的簽核者參考。

!!! abstract "作業：在流程加入 AI 分析"
    **MENU**：表單流程 ／ 流程設計 → 編輯 → 左欄「系統整合」

    1. 把「AI 分析 (AiAgent)」拖進畫布
    2. 「要分析的內容」填要送給 AI 的資料，例如 `${f.raw_request}`
    3. 「結果寫入變數」取一個名字，例如 `ai`
    4. 儲存，然後回配對管理「新發行」

!!! danger "這個節點會用掉配額，而且是**估算成本**"
    每次執行都會記在[AI 用量與配額](ai_usage.md)。**配額用完時節點一律當作錯誤處理**，
    不會因為下面設了「繼續流程」而放行——那代表 AI 根本沒看過這張單，
    靜默略過會讓簽核者誤以為已經分析過。

## 設定面板

| 欄位 | 說明 |
|---|---|
| 給 AI 的指示 | 留空使用預設（HTTP 流量安全分析器）。要分析別的東西就自己寫 |
| 要分析的內容 | **必填**。可用 `${f.欄位}`、`${v.變數}` |
| 結果寫入變數 | **必填**。後續節點用這個名字取用 |
| 模型 | claude-sonnet-5（預設）／ claude-opus-5 ／ claude-haiku-4-5 |
| 逾時（秒） | 預設 60 秒 |
| 自動解碼 | 對內容做 Base64／URL 解碼，最多 3 層，預設開啟 |
| 寫成簽核註記 | 預設開啟 |
| AI 失敗時 | 視為節點錯誤（走 error 邊）／ 繼續流程（只留規則層結果） |

## 分析結果怎麼取用

假設「結果寫入變數」填 `ai`，流程裡可以用這些：

| 變數 | 內容 |
|---|---|
| `${v.ai_verdict}` | `malicious` ／ `suspicious` ／ `benign`；分析失敗時是 `unknown` |
| `${v.ai_score}` | 風險分數 |
| `${v.ai_rule_hits}` | 規則層命中幾項 |
| `${v.ai_note}` | 寫進簽核註記的那段文字 |
| `${v.ai_ok}` | AI 這次有沒有正常回答 |

**分支節點要判斷結果，只能用上面這些攤平後的變數**。寫成 `${v.ai.verdict}` 取不到值，
條件會永遠不成立，整批單會落到預備路徑——而且不會報錯。

## 畫面上看不出來的規則

### AI 只出文字，不會動任何資料

所有寫入（流程變數、簽核註記、表單欄位）都是平台自己做的。
節點不會讓 AI 去改單、去簽核、去執行指令。

### 規則層的偵測不經過 AI

平台自己會掃內容裡有沒有「叫 AI 忽略指示」「叫 AI 回報無害」這類特徵。
這個判定**不經過 AI，一定生效**：

- 規則命中時，註記開頭會加上系統警示，且**AI 拿不掉它**
- 規則命中、AI 卻說「無害」時，判定會**自動升級為可疑**——兩邊矛盾就從嚴

### 答非所問的輸出一律作廢

每次送出的內容裡藏了一組隨機字串，要求 AI 原樣回傳。回傳不符就代表這次的輸出
已經被送進來的資料帶偏，**整份作廢，不會重試到通過為止**。這時的結果等同分析失敗，
依「AI 失敗時」的設定處理。

### 簽核註記不是簽核

AI 寫的註記在簽核紀錄裡是參考資料，**不會被算成同意或退回**，
也不會讓需要人簽的關卡自動放行。

### 主機要先裝好 AI CLI

這是選用功能，要由安裝人員在主機上完成安裝與登入。沒裝好時節點每次都失敗，
原因會顯示在[AI 用量與配額](ai_usage.md)的執行明細（例如尚未登入、找不到程式）。
自己的企業沒有要用這個節點，整頁可以略過。

## 常見問題

**AI 判定一直是 `unknown`**——分析沒成功。到 AI 用量明細看該筆的錯誤訊息，
常見的是主機端沒裝好、逾時、或輸出未通過驗證。

**分支永遠走同一條路**——條件用了 `${v.結果.verdict}`。改用 `${v.結果_verdict}`。

**明明還沒用幾次就被擋**——配額是**企業**共用的，不是每張單各自計算；
另外估算成本上限也會擋。到 AI 用量頁看今日／本月的使用量。
