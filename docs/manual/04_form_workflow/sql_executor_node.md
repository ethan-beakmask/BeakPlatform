# SQL 執行節點

在流程中途查一筆資料回來（庫存、額度、既有紀錄），用它決定後面要走哪條路，
或把結果寫成註記給簽核者看。

本節點為系統級受限節點，需由平台管理員授權貴企業後才會出現在設計器的「系統」分類中。

!!! abstract "作業：在流程加入查詢"
    **MENU**：表單流程 ／ 流程設計 → 編輯 → 左欄「系統」

    1. 把「系統 SQL 執行 (SysSqlExecutor)」拖進畫布
    2. 「預存程序」下拉選要用的查詢——選好之後，下方會依這支查詢**自動出現它要的參數欄位**
    3. 參數填值，可用 `${f.欄位}` 帶入表單內容
    4. 「結果寫入變數」取一個名字
    5. 儲存，然後回配對管理「新發行」

## 只能選清單裡的查詢，不能自己寫 SQL

下拉選單裡的每一支查詢都是平台事先登錄的。**這是刻意的**：登錄一支查詢等於授權
所有流程設計者去查那份資料，屬於部署時的決定，不開放在畫面上新增。

需要新的查詢時，把「要查什麼、給誰用」告訴貴公司的平台管理員，由他登錄。

另外兩件由平台強制、設計者改不掉的事：

- **企業識別碼由系統自動帶入**，設定裡指定不了——所以查不到別家企業的資料
- **查詢一律唯讀**，這個節點寫不了任何資料

## 查詢結果怎麼取用

假設「結果寫入變數」填 `stock`，依該查詢的回傳型態而定：

| 回傳型態 | 取用方式 |
|---|---|
| 單一數值 | `${v.stock}` |
| 單列多欄 | `${v.stock_欄位名}`，例如 `${v.stock_qty_on_hand}` |
| 多列 | `${v.stock}` 是整份清單，通常搭配下面的筆數變數使用 |

三種型態都會另外給這幾個：

| 變數 | 內容 |
|---|---|
| `${v.stock_count}` | 查到幾筆 |
| `${v.stock_found}` | 有沒有查到 |
| `${v.stock_truncated}` | 是否因超過筆數上限被截斷 |

**分支節點要比大小，用攤平後的 `${v.stock_qty_on_hand}` 這種變數**，
寫成 `${v.stock.qty_on_hand}` 取不到值。

查詢失敗時 `_found` 為否、`_count` 為 0，另外多一個 `_error`。
會這樣設計是為了讓後面的節點看得出「這次沒查到」，而不是拿到上一輪的舊值。

## 畫面上看不出來的規則

### 註記樣板沒有條件語法

「註記內容樣板」只會做變數代換，不能寫「如果查無資料就改講別的話」。
查無資料時，樣板裡的變數會變成空白，印出來像是漏字。

所以**註記只放三種結果都成立的事實**（例如「查得 N 筆」），
分歧的措辭交給分支後面的「寫入欄位」節點各寫各的。

### 查詢失敗時，簽核者只會看到固定訊息

註記不會寫出資料庫的錯誤內容——那會洩漏內部結構。詳細原因留在流程執行紀錄裡。

### 註記不是簽核

跟 AI 分析節點一樣，這個節點寫的註記是參考資料，不會被算成同意或退回。

## 常見問題

**下拉選單是空的**——這套安裝還沒登錄任何查詢，找平台管理員。

**參數欄位沒出現**——先選「預存程序」，欄位是依所選查詢動態產生的。

**查得到自己的資料，查不到分公司的**——正常。企業識別碼是系統帶入的，
跨企業查詢不會經由這個節點提供。
