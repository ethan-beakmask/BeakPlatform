# 流程設計

!!! abstract "作業：建立流程"
    **MENU**：表單流程 ／ 流程設計

    1. 按「+ 新增工作流」，填名稱、選分類
    2. 按「編輯」進設計器
    3. 從左欄「流程元件」把節點拖進畫布
    4. 點節點，右欄「設定面板」填該節點的設定
    5. 節點之間拉線決定先後順序
    6. 按「儲存」

一張流程要能被人使用，還要跟表單配對並發行，見[配對管理與發行](mappings.md)。
**配對完成之後不必等發行，設計者就能立刻試跑**，見下方「發行前測試」。

```mermaid
flowchart LR
    T[表單範本] --> M[配對]
    W[流程設計] --> M
    M -->|發行前測試| D[設計稿試行]
    D -->|改設計，再測一次| M
    M -->|發行| S[發行版本]
    S --> C[表單中心可送單]
```

## 發行前測試

配對一建立，表單中心就會多出一張同名的表單，名稱前面標著 `TEST`。
點它送出的單，跑的是**設計器裡當下那張圖**，不是快照——改一個節點、存檔、再送一張，
新行為馬上就看得到。測試單的單號前綴是 `TEST-`，和正式單一眼分得出來。

**這張測試表單只有設計者看得到。** 判定依據是「試行設計稿」權限，
出廠給了**流程設計師**與**表單設計師**兩個角色（企業管理員也一併涵蓋）。
一般員工與外部廠商在表單中心完全看不到它，也送不出去。

測試單跑完，在表單中心按〔刪除測試表單〕可以整批清掉——只會刪自己送出的、
已經結束的測試單。

### 同一份設計為什麼會存兩份

因為「還在改的」和「大家在用的」必須互不干擾：

| | 設計稿 | 發行版本 |
|---|---|---|
| 誰跑得動 | 只有設計者，走 `TEST` 表單 | 依填寫權限開放給使用者 |
| 改了設計 | **立刻生效**，隨改隨測 | 不受影響，要重新發行才換 |
| 送出的單 | 單號 `TEST-` 開頭 | 正式單號 |
| 已送出的單 | 設計改了就對不起來，不必追 | 照它當初那一版跑完 |

### 發行之後誰看得到這張表單

發行版本的可見範圍由配對管理的〔權限〕決定，規則在[配對管理與發行](mappings.md)，
這裡只講三個預設值：

- **沒設任何規則**（出廠狀態）：持有「企業成員」角色的一般員工看得到
- **設了規則**：只有符合規則的人看得到；規則可指定角色、部門（可含子部門）、
  社群（可含下層）或個人
- **外部廠商**：預設看不到任何表單，因為它不是企業成員。要開放只能用「社群」授權

## 節點分成八組

左欄依用途分組，展開才看得到組內的節點。

| 組 | 用途 | 組內節點 |
|---|---|---|
| 基本節點 | 流程的收尾 | 結束 |
| 表單處理 | 交給人簽核 | 簽核 |
| 通知機制 | 送出訊息 | Telegram 通知、Email 通知、跑馬燈廣播、緊急廣播 |
| 流程控制 | 決定走哪條路、等多久 | 分支、匯合、並行分支、並行匯合、暫停、子流程 |
| 資料處理 | 讀寫表單欄位與流程變數 | 設定變數、讀取欄位、寫入欄位、人事資料取值 |
| 系統整合 | 呼叫平台以外的能力 | [SQL 執行](sql_executor_node.md)、[AI 分析](ai_agent_node.md)、子系統配置 |
| 安全管控 | 機器處置 | API Key 處置 |

起點（Start）是每個流程本來就有的，不必自己拉。

結束節點的**結束模式決定案件最後被記成什麼**：

| 結束模式 | 未完成的節點 | 案件最後的狀態 |
|---|---|---|
| 分離執行（預設） | 不主動處理（引擎會擋住它們往下推進） | 已核准 |
| 取消/終止 | 一律取消 | **已取消** |
| 嚴格等待 | 等全部完成才結束 | 已核准（有節點失敗則為錯誤） |

所以案件是「談成了」就走分離執行或嚴格等待，是「不做了、退掉、擋下來」
就走取消/終止——用錯的話，被擋下來的案子會在表單中心顯示成「已核准」，
或正常結案的案子顯示成「已取消」。
（舊版另有獨立的「中止」節點，已併入「取消/終止」模式。）

## 畫面上看不出來的規則

### 儲存不等於生效

表單中心跑的是**發行版本的快照**，不是設計器裡的圖。改完流程按了儲存，
使用者送的單還是照舊版走，**而且不會有任何提示**。改完一定要回配對管理按「新發行」。

例外是**還沒發行過的配對**：這種配對直接採用設計圖，所以設計中的流程可以邊改邊測試，
見上方「發行前測試」。

### 「儲存」與「另存新版」

「儲存」改的是同一份流程，已發動的單不受影響（它們跑的是自己那一版的快照）。
「另存新版」複製一份新的流程，原本那份留著。想保留舊設計又要大改時用後者。

### 引用資料的寫法

節點設定裡可以帶入流程中的資料，寫法固定：

| 寫法 | 取到的東西 |
|---|---|
| `${f.欄位識別碼}` | 表單欄位值 |
| `${v.變數名}` | 流程變數 |
| `${wi.exec_code}` | 流程編號，例如 `OD-20260821-0003` |

**變數是平的，`${v.結果.欄位}` 這種寫法取不到值**（結果會變成空字串）。
會回傳多個欄位的節點都會另外攤平成 `${v.結果_欄位}`，要比大小、判斷內容就用攤平的那個。

### 分支節點會走完每一條命中的規則

分支不是「命中第一條就停」，**所有條件成立的規則都會展開**。規則之間沒有互斥時，
一張單會同時往好幾條路跑。

條件列的「且／或」是**分組符號**：遇到「或」就切一組，同組之內是「且」，組與組之間是「或」。
想表達「A 且 B」，兩條都要標「且」。

欄位沒有值或型別對不上時，該條件一律判定為不成立。可以刻意利用這點，
讓資料不齊的單落到預備路徑。

### 結束節點決定其他分支的下場

三種結束模式對其他分支的影響：

| 模式 | 行為 |
|---|---|
| 分離執行（預設） | 直接結束；還沒跑完的節點不會再往下推進（計時分支到期後就地失效），但**等待中的簽核任務會留在待辦清單**，不會被主動作廢 |
| 取消/終止 | **中止流程**：取消所有未完成節點（含簽核任務），案件記「已取消」 |
| 嚴格等待 | 等全部節點完成才結束 |

另外，**結束節點是流程層級的**：並行的兩條路只要有一條走到結束，整張單就結束了，
另一條上的簽核任務會被視為流程已結束。要讓某條分支安靜收尾，
就讓它的最後一個節點**不要連出任何線**，不要接到結束節點。

### 子流程裡的結束節點：取消/終止只中斷自己那一串

結束節點放在**子流程**裡時，三種模式同樣有效，其中「取消/終止」的範圍是
**子流程自己與它再往下呼叫的所有子流程**——上層流程不受影響，會照常繼續跑。
上層的子流程節點會收到「下層是完成還是中止」，可在子流程節點設定的
**「下層結束路由」**指定：完成走哪條線、中止走哪條線（不設定就走所有出線）。
流程變數 `${v.節點ID_result}`（值為 `completed` 或 `cancelled`）也帶有同一個結果，
可供後續的分支節點或訊息內容引用。

### 子流程可以重複執行，但要自己設上限

同一個子流程節點被迴圈重複執行是正常用法，**平台不會自動偵測無限循環**。
含迴圈的設計請在子流程節點設定**「執行次數上限」**，超過上限時該節點會以錯誤中止，
避免流程無限繞圈。

### 沒有連出去的節點是安靜結束

節點後面沒有接線不會報錯，該分支就到此為止。這是正常用法，不是漏接。

## 常見問題

**改了流程，使用者送的單還是舊的**——沒有重新發行。見上方「儲存不等於生效」。

**流程卡在某個節點不動**——先看該節點是不是在等人簽核（簽核節點）或等時間到（暫停節點）。
都不是的話，到表單中心開該筆單的流程圖，節點上會標示執行狀態與錯誤訊息。

**節點設定填了變數，執行結果是空的**——變數名稱打錯、或用了 `${v.a.b}` 這種巢狀寫法。
把節點實際寫出的變數名稱抄下來用。
