# 卡住時對照這張表

每個錯誤都精準對應到[逐步建置](02_build_it.md)的某一步沒做完。

| 收到 | 是哪一步 | 怎麼修 |
|---|---|---|
| `401 auth_failed` | 步驟六 | 見下方「401 的四種原因」 |
| `403 scope_denied` | 步驟六 | 金鑰沒勾 `od_intake` 授權範圍 |
| `403 source_not_allowed` | 步驟六 | 送出的來源系統名稱不在金鑰白名單內，兩邊要完全一致 |
| `422 no_mapping` | 步驟五 | 沒有任何路由規則命中。先加一條條件全空、優先序 0 的規則 |
| `422 form_not_published` | 步驟四 | 配對建了但沒發行，或改過設計後沒重新發行 |
| `400 validation_error` | 事件內容 | 回應的 `details` 會逐欄說明缺什麼 |
| `429` | 送太快 | 每把金鑰每分鐘 100 筆、每小時 5000 筆。退避後重試 |

## 401 的四種原因

平台對所有認證失敗一律回同一個 `auth_failed`，**刻意不區分原因**（避免被用來探測），
所以要自己逐項排除：

1. **secret 沒有先做 base64 解碼**——這是最常見的一種。畫面上顯示的 secret 是
   base64 字串，簽章用的金鑰是它解碼後的 32 個位元組。直接拿字串當金鑰會一直失敗。
   用範例程式就不會踩到
2. **主機時鐘不準**——時間戳超過平台時間正負 5 分鐘就拒收。分析主機請確認有做 NTP 同步
3. **金鑰被暫停或撤銷**——到「系統安全 ／ API Key 管理」看狀態
4. **來源 IP 不在金鑰的白名單**——金鑰有設 IP 鎖定時才會有這個限制

## 沒有錯誤，但東西沒出現

這一類最難查，因為兩邊都「成功」了：

| 症狀 | 原因 |
|---|---|
| 案件建得起來，處置中心卻看不到 | 表單掛的分類不是資安分類（識別碼前綴不對），見[步驟一](02_build_it.md) |
| 處置中心統計有數字、清單空的 | 「僅我可簽核」預設開著，你的帳號沒有簽核角色 |
| 事件內容某幾格永遠空白 | 表單裡沒有那個欄位，或欄位識別碼拼錯 |
| 改了流程，行為完全沒變 | 沒有重新發行，事件讀的還是舊快照 |
| 案件開了就沒有下文 | 流程的簽核節點沒指定處理人，或指定的角色沒有成員 |
| 送成功但案件數沒增加 | 冪等或聚合，見[送出第一筆事件](03_send_and_verify.md)最後一節 |

## 還是查不出來

把送出時的完整回應留著（範例程式失敗時會把 HTTP 狀態、錯誤碼與逐欄說明一起印在
標準錯誤輸出），連同事件的 `correlation_id` 一起交給平台管理員。
`correlation_id` 是查詢這筆事件的唯一線索。
